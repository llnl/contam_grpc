# Contam simulation server (contam\_grpc)

Contam simulation server takes a contam project file (`*.prj`) via RPC from a client, runs the simulation defined in the project file, and returns the result.
The results are a group of files generated as a result of running a simulation as well as `stdout` and `stderr`.


## Getting started

This codebase includes both the server and the client examples.
To build only the client part, use the cmake option `-DCLIENT_ONLY=ON`
If you want the client to run with MPI, use the cmake option `-DMPI_CLIENT=ON`

The follwing steps
- clones the code
- sets the essential environment variables for the server
  - `CTMX_LIB_DIR`
  - `CTMX_INC_DIR`
  - These are not needed when building only client with `-DCLIENT_ONLY=ON`
- sets an optional environment variable
  - `gRPC_DIR`: location of grpc installation. If the path is not specified, or gRPC cannot be found, it will be downloaded and built. gRPC needs to be installed with `ABSL_ENABLE_INSTALL=ON`
- builds the project and install
- starts the server up at the default port 50051

```sh
git clone https://lc.llnl.gov/gitlab/yeom2/contam_grpc.git
cd contam_grpc
mkdir build
cd build
export CTMX_LIB_DIR=<path to libcontamx-lib.{a|so}>
export CTMX_INC_DIR=<path to libcontamx-lib header>
export gRPC_DIR=<path to gRPC installation>
cmake -DCMAKE_INSTALL_PREFIX=`realpath ..`/install ..
make -j 4
make install
cd ../install/bin
hostname
./contam_server
```

To stop the server, press ctrl+c.

To run a client, identify where the server is running.
`hostname` can be used. Suppose that the server and client are running on the same host.

Then, for example, run the client as

```sh
./contam_grpc --ctm_target=localhost:50051 \
  --ctm_prj_file=testOneZoneWthCtm-UseApi.prj
```

Optionally, the following options can be used

```sh
  --ctm_of_prefix="ctm/"
  --ctm_out=true --ctm_err=true
  --ctm_ach=true --ctm_cex=true --ctm_csm=true --ctm_log=true --ctm_rst=true --ctm_sim=true --ctm_xlog=true
```


## Options and defaults
- contam\_server:
  - `--port=<port number>` : The default port is 50051.
  - `--ctm_of_prefix=<>` : This defines a prefix to the files that are generated by running a simulation. The default is `/tmp/ctm_`
- main_app (contam_client):
  --ctm_target=<server address> : The default is "localhost:50051"
  --ctm_prj_file=<Contam project filename> : Without a valid filename, the client will exit.
  --ctm_of_prefix=<prefix to contam output filenames> : The default is "". This can be used to specify a directory to contain all the output files. e.g., "ctmout/".
  --ctm_out=<true|false> : The default is false. Write stdout from the server to .out file.
  --ctm_err=<true|false> : The default is false. Write stderr from the server to .err file.
  --ctm_ach=<true|false> : The default is false. Tells the server to return .ach output file.
  --ctm_cex=<true|false> : The default is false. Tells the server to return .cex output file.
  --ctm_csm=<true|false> : The default is false. Tells the server to return .csm output file.
  --ctm_log=<true|false> : The default is false. Tells the server to return .log output file.
  --ctm_rst=<true|false> : The default is false. Tells the server to return .rst output file.
  --ctm_sim=<true|false> : The default is false. Tells the server to return .sim output file.
  --ctm_xlog=<true|false> : The default is false. Tells the server to return .xlog output file.


## RPC API
- `proto/contam.proto` defines RPC API for both server and client.
- client packs `*.prj` file into a message sent to a server.
- client also indicates if it wishes to receive each of contam output files: `*.ach`, `*.cex`, `*.csm`, `*.log`, `*.rst`, `*.sim`, and `*.xlog`.
- server packs each of requested output files into a message and returns it to the client.


## Container
As the contamx library is distributed in a binary form, there can be an ABI incompatibility with glibc,
especially if the server environment relies on an older glibc than the one used by the contamx library.
In such as case, the server may need to be built in a container where glibc is compatible.
The client on the other hand does not directly rely on the contamx library. It only interacts with it via the server based on gRPC.

- `container` folder contains `Dockerfile`.
- On Livermore Computing (LC) clusters, podman is supported. The following steps show how to build and run a container image.
  - LC guide: [https://hpc.llnl.gov/documentation/user-guides/using-containers-lc-hpc-systems]
- When container is launched it will share the folder `data` with the host.

```sh
. /collab/usr/gapps/lcweg/containers/scripts/enable-podman.sh
cd container
./copy_src.sh
podman build -f Dockerfile -t contam-grpc
podman save -o contam-grpc.tar localhost/contam-grpc
podman load -i contam-grpc.tar
podman run -p 50051:50051 -v $PWD/data:/data --rm -it localhost/contam-grpc
```

## Requirements
- Contamx C library and headers
  - Currently, the headers are not publicly available. We assume that the tarball,
    `runContamxDll_OneZoneWthCtm.tar.gz`, which includes the shared library `libcontamx-lib.so`
    and headers, is available in the `container` directory where Dockerfile is located.
    In the Dockerfile, the tarball is extracted and two environment variables, `CONTAM_LIB_DIR`
    and `CONTAM_INC_DIR`, are set to the directories containing the library and the headers, respectively.
    Once these components become publicly available, we will update the process to download them from
    the public repository.
- gRPC with ABSL component and protobuf (proto3)
